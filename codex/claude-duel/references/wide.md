# Wide mode

Use when the deliverable is a range of viable options, explanations or
perspectives. `--blind` alone still aims for one conclusion; wide mode
preserves defensible alternatives. Always two reviewer turns.
Use [runtime](runtime.md) for both calls; the main skill's handoff rules apply.

1. Form the lead's candidate list before reading the reviewer. Send only the
   question, facts, constraints, sources and neutral evidence gaps in round 1,
   including no files that reveal the lead's candidates or preferences.
   Ask the reviewer for its own list. Each candidate needs support, conditions
   under which it holds and its main weakness. Distinguish verified facts from
   judgment. Do not pad the list or claim completeness.
2. Merge the lists, preserving differences in conditions, mechanism or
   consequences. Tag origins `[Codex]`, `[Claude]` or `[both]`; the last
   means independent discovery, not equal ranking. Add the lead's assessment.
3. With `--steer`, show that compact map and pause for the user to deepen,
   drop or add entries or constraints. Wait before round 2. Remove dropped
   entries from the next handoff and renumber; record drops in the final
   answer as user choices, not refutations.
4. Resume the same session with the merged map, assessments and any steering.
   Ask for missing candidates, unjustified merges, weak claims, remaining
   disagreements and rankings where comparable, with criteria. Include entries
   the reviewer has not assessed. Fold the response into the map without
   averaging rankings.

Return surviving candidates with origins, conditions, weaknesses and the
lead's assessment; briefly identify refuted candidates or claims. Preserve
remaining differences with each side's reasons. Recommend only when asked,
as the lead's judgment. State assumptions, any steering, reviewer settings
and two completed turns. The main skill's code verification rule still applies.
